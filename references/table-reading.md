# 读场与记牌

## 对手牌库还有几张潮

1. 从最近的 `ws_game_state` 或 `ws_play` 返回取 `p = 1 - obs.seat` 和 `N = obs.players[p].deck`。对该席的 `wr/clock/level/memory/climax`、舞台角色及其标记、可见手牌，逐张读取可辨认的实体。只有 `type:"X"` 计潮。在 `cards` 里找不到资料时，将缺少的内部 `id` 去重，分批调用 `ws_card_info`。返回 `null` 的牌保留为未知。
2. 按实体 `u` 去重，同一卡号的不同实体各算一张。确认已从牌库取出的触发牌、伤害解决牌可暂记在库外。`resolution.kind:"dmgBoth"` 用每张牌的 `p` 分席。展示窗 `show`、`look`、`context.shown`、选项和卡文表都可能重现同一张牌。查看库顶时牌甚至还在牌库。先确认所属区域与去向再入账。
3. 设 `V` 为**此刻**确认在库外的潮数。通常双方的牌各自在自己一侧，标准构筑下牌库潮数 `K` 至多是 `min(N, 8 - V)`。确认仍在手牌或库存的潮也可计入 `V`，一张只算一次。曾经见过但去向已失去依据的潮，只记「曾见」。有异主卡跨席移动时，先核对原牌组及实际流入、流出的卡。归属不明时只报可确认的数量。
4. 只有从给定牌表等证据确认了总潮数 `T`，才能用它代替 8。设 `H` 是库外身份未确认的卡位数，则下界为 `max(0, T - V - H)`。另知仍在库里的潮可提高下界，仍在库里的非潮可压低上界。重洗后按新区域重算，原休息室的潮已经回流，留意新库顶进时计的那一张。

**例。** 对手 3/6，牌库 12 张，休息室有 4 张潮、时计有 1 张，其中一张还显示在展示窗口。能确认 5 张库外，牌库有 **0～3 张**。若又能确认另一张潮仍埋在对手库存，则是 **0～2 张**。两条结论都不要求知道对手的隐藏手牌。

若库顶顺序未知且近似随机，本包普通伤害 `d` 张都从当前牌库翻出，给定库中恰有 `K` 张潮，则

```text
P(取消 d 点) = 1 − C(N − K, d) / C(N, d)
```

`C` 表示组合数。把 `K` 的两端代入，就得到取消率范围。上例按 0～3 张算，1 点为 0～25%，3 点为 0～61.8%。己方为 3 魂，面对 2 级角色且无其他修正时，正攻 3 点和侧攻 1 点都够致胜。若此刀只求通过伤害，侧攻更合适。若本题实际提供 `{"id":"attack:0:side:2","attackType":"side","defender":2,"soulDelta":-2}`，提交该选项的 `id`。触发图标可能再加魂。库顶顺序已知时先判断已知部分。一包可能翻进新库或有伤害替换时，按实际过程分段分析。

有 Python 3.8 或以上版本时，可在技能目录执行下列命令。第一个文件是本题快照，其余可选文件各是一次 `ws_card_info` 的结果。脚本接受解包后的对象或原始 MCP 响应，快照也可用 `-` 从标准输入传入。第二例适用于牌表已确认共 8 潮的情况。[数潮脚本](../scripts/count_cx.py)

```sh
python3 scripts/count_cx.py state.json --damage 3
python3 scripts/count_cx.py state.json info.json --total-cx 8 --damage 3
```

默认算对手，`--seat 0` 或 `--seat 1` 可指定。输出列出确认的库外潮、缺资料需补查的卡号、库内区间和可计算的普通伤害取消率。脚本只读这一帧，假设每方原有 50 张且牌未跨玩家转移。手记里能确定的库存、库顶等信息要另外合并。仅有 MCP 的客户端可直接用上面的四步。

## 一个能力现在能做什么

- 先看双方舞台，包括后列。根据这次选择，把攻击者、防守者、支援者以及相关高潮、时计顶或回忆卡的内部卡号放进同一批 `ws_card_info`。在 `cards[id].text` 和 `ab` 中找 **谁、什么时机、在哪个区、满足什么条件、付什么、对谁生效、持续多久**。
- `ab.statics` 对应【永】，查目标与 `when`。当前舞台数值已含生效修正。`ab.autos` 对应【自】，查 `on/when/cost/fx/limit`。同一时点用 `pickPending` 的 `cid/label/text` 决定先后。若先结算一个效果会洗牌，而另一个要用已知库顶，就先利用库顶。`ab.acts` 对应【起】，`ab.backup` 是助太刀，`ab.fx` 可给出事件效果。
- 印刷资料可以跨题复用。实际是否能发动，查本题的 `act/zoneAct/counter` 等选项。舞台可能有临时授予、封锁、限次或改值，MCP 的舞台格没有完整能力清单。以已观察到的结算、舞台有效值、当前选项三者相互核对。某个窗口没有询问，只能说明此时没有该选择。

**实卡例。** 若见 `BDY-W135-057`「いっぱい送った写真 宮永ののか」，查卡可读到两个【自】。从手牌登场时回复需要 1 库存和弃 1 手牌。另一能力在己方**其他《音楽》角色攻击**时使它本回合战力 +2000。它现在 3500，正对 5000，另有一名可攻击的《音楽》角色时，先用那一名攻击，拿到新题再读该格战力。若变为 5500，可考虑正攻。仍要计入对方反击和击倒收益。已经体现在 5500 里的加成无需再加一次。

## 跨题只记会改变下一步的事实

使用本席可见的 `obs`、当前提问和自己已结算的选择。按局维护简短笔记，实体写 `u + id`，另记所属席、位置、证据和失效条件。自己的私看可用于自己的决策。`id:"_"`、`hidden:true`、负数占位 `u` 都不能作为牌的身份。`obs.events` 只有最近的回合和发言。两个提问之间可能自动结算多步。如果只看到了战力增加，翻牌窗口已经过去，就只记加成，把具体牌号留空。

| 已确认的事实（示例） | 下一题如何更新 |
| --- | --- |
| 自己刚用效果按顺序放回顶牌 A、B | 第一张在顶。若只抽走 1 张，A 去手，B 成新顶。若检索后洗牌，清空顶序。发生了无法重建的取牌时，撤销受影响的精确位置。摆顶前想清楚下一次是自己触发、抽牌，还是对手打来要自己翻伤害。 |
| 刚确认一张普通触发潮在己方库存顶 | 后续有 2 张普通触发明确叠上去，它是从顶往下数的第 3 张。普通支付 2 后它到顶，再付 1 才进休息室。若卡文有库存底支付、换库、额外进库或去向不明，按实际路径更新。只看库存总数的净变化无法还原顺序。 |
| 对手通过效果公开把某张助太刀加入手牌 | 记「已公开入手」和库存、等级要求。若它作为时计或弃牌公开移走，销账。中间有未公开的手牌变动且可能移走它，就降为「可能仍在手」。用它评估正攻战力差。 |
| 角色本回合获得能力，或某个格位上的限次已用 | 记来源、受益角色、时限。角色换格时追踪该实体。同一张实体离场再登场时，按新舞台状态重查。按能力文字区分本回合、每局及同名共享的次数。 |

同一 `decisionId` 重读、同一张牌从展示移到休息室，都只更新当前位置。换新席位码时清空本局笔记。同一局断线后从最近快照恢复，把缺口内无法证实的位置标为未知。对用户解释决策时，说清可确认的事实、范围如何改变选择，并按对方可见范围分享。

要复盘一手，就在提交前记下题号、当时双方的等级/时计、选项 ID 和用到的卡文。一次 `ws_play` 的回包可能已经跨过对手整个回合。解释当时为何攻击、放时计或支付费用，要用提交前的数值。
